What v0.1.1 includes

협업과 운영을
서로 방해하지 않게.

사용자 작업 공간, 개인화, 서비스 관리 영역을 URL과 권한으로 나눴습니다. 아래 내용은 v0.1.1에서 화면과 API로 확인한 범위입니다.

01

채널 중심 협업

팀과 채널에서 메시지, 스레드, 파일, 반응을 사용하고 중요한 글과 예약 메시지를 개인 보기에서 관리합니다.

  • 공개·비공개 채널과 DM
  • 스레드·검색·저장 글
  • Lease와 결과 ID로 보호하는 예약 발송
02

AI·MCP와 내부 연동

Keycloak OIDC와 OpenAI 호환 AI를 연결하고, REST·MCP·예약·Webhook·Slash 게시를 같은 application command 정책으로 처리합니다.

  • 스트리밍 AI와 Streamable HTTP MCP
  • 필요한 MCP 쓰기에 선택적 승인
  • PostgreSQL 기반 outgoing webhook 재시도
03

보안과 안정적 운영

권한·감사 경계를 유지하면서 DB 변경, 세션 조회와 프런트 화면 로딩의 변경 범위를 작게 나눴습니다.

  • 체크섬과 advisory lock을 쓰는 migration
  • HMAC JTI 세션 lookup expand 단계
  • SMTP capability와 route-level lazy loading

Predictable boundaries

외부 계약은 익숙하게,
내부 구조는 작게.

Mattermost 화면의 픽셀 복제가 아니라 REST API v4, WebSocket, 인증, 봇과 웹훅 같은 공개 경계의 호환을 지향합니다. v0.1.1의 REST·MCP·예약·Incoming Webhook·Slash 게시 경로는 공통 command를 사용하며, 예약 worker는 lease와 결과 post 고유 키로 중복 게시를 방지합니다.

Answers first

자주 묻는 질문

v0.1.1의 배포와 연동 범위를 기준으로 답합니다.

moyro는 인터넷이 없는 환경에서 운영할 수 있나요?

네. 릴리스의 moyro-v0.1.1.tar.gz를 내부망으로 반입해 Docker에 로드하고, 내부 PostgreSQL과 네 가지 환경변수로 실행합니다.

Mattermost와 완전히 같은 제품인가요?

아닙니다. 화면을 그대로 복제하지 않고 REST API v4와 WebSocket 등 공개 호환 경계 및 익숙한 채널 흐름을 지향하는 독립 구현입니다.

Keycloak과 사내 AI는 인터넷 없이 연결할 수 있나요?

네. 먼저 canonical Site URL을 저장한 뒤 내부 Keycloak issuer와 OpenAI 호환 AI endpoint를 설정합니다. 컨테이너에서 해당 내부 endpoint에 접근할 수 있어야 하며, 두 기능은 활성화하기 전까지 사용되지 않습니다.

검토와 승인 절차는 항상 표시되나요?

아닙니다. 관리자가 승인 정책을 활성화한 경우에만 관련 사용자 메뉴와 요청·검토 화면이 표시됩니다.

SMTP를 설정하지 않아도 이메일 발송 완료로 기록되나요?

아닙니다. v0.1.1의 지원 설정에서 SMTP host가 없으면 이메일 capability가 비활성으로 표시되고 digest worker도 시작하지 않습니다. SMTP 관리 설정과 테스트 메일은 아직 지원하지 않습니다.

Outgoing webhook은 프로세스 재시작 뒤에도 재시도되나요?

네. callback 작업과 시도 이력은 PostgreSQL에 저장되며 lease, backoff와 dead 상태를 사용합니다. 다만 post 저장과 queue 등록은 아직 하나의 DB transaction이 아니므로 완전한 domain-event outbox 원자성은 다음 단계입니다.

moyro v0.1.1을 여러 애플리케이션 replica로 운영할 수 있나요?

아닙니다. v0.1.1의 지원 토폴로지는 외부 PostgreSQL에 연결된 moyro 애플리케이션 컨테이너 한 개입니다. Redis fan-out과 multi-replica 설정 전파는 지원하지 않습니다.

moyro native plugin은 sandbox에서 실행되나요?

아닙니다. v0.1.1의 native plugin 실행 파일은 서비스 UID, 컨테이너 namespace, volume과 network를 공유하는 완전 신뢰 코드입니다. 검토하고 승인한 운영자 제공 binary만 설치해야 합니다.
