01

Moyro Flow

글로벌 레일에서 오늘, 내구성 있는 활동 알림함, 대화, 내 업무, 검색과 승인을 독립 URL로 오갑니다.

  • 멘션·DM·답글·승인·리마인더·작업 활동을 PostgreSQL에 보존
  • 메시지에서 담당 작업과 근거가 남는 결정을 생성
  • 저장·예약·리마인더·작업·결정을 내 업무에서 관리
  • 46개 실제 화면의 route·상태·plugin workflow 계약
02

대화 맥락과 실제 AI

채널의 스레드·요약·파일·정보를 한 패널에서 보고, 권한과 개인 설정을 적용한 실시간 AI 응답을 사용합니다.

  • 사용자가 실행하는 최근 메시지 요약
  • 안전한 Markdown과 재생성·편집을 제공하는 세션 한정 AI 대화
  • 접근 가능한 팀 범위 메시지 검색
03

승인과 운영 경계

승인 센터는 비밀값과 원시 실행 payload를 제외한 안전한 미리보기를 제공하고, 운영 현황은 PostgreSQL·Migration·큐·Webhook·저장소의 확인 가능한 근거만 표시합니다.

  • MCP 보호 작업의 내 요청·검토 대기와 구조화된 영향 정보
  • 로컬·세션·비활성 초안 저장 정책과 만료·로그아웃 삭제
  • 검토된 Trusted Native tar.gz 관리와 네 archive의 제한된 기능 E2E

Answers first

자주 묻는 질문

v0.2.5 릴리스의 배포와 연동 범위를 기준으로 답합니다.

moyro는 인터넷이 없는 환경에서 운영할 수 있나요?

네. v0.2.5 릴리스가 게시된 뒤 moyro-v0.2.5.tar.gz와 SHA-256을 확인해 내부망으로 반입하고, 내부 PostgreSQL과 네 가지 환경변수로 실행합니다.

Mattermost와 완전히 같은 제품인가요?

아닙니다. 화면을 그대로 복제하지 않고 REST API v4와 WebSocket 등 공개 호환 경계 및 익숙한 채널 흐름을 지향하는 독립 구현입니다.

Keycloak과 사내 AI는 인터넷 없이 연결할 수 있나요?

네. 먼저 canonical Site URL을 저장한 뒤 내부 Keycloak issuer와 OpenAI 호환 AI endpoint를 설정합니다. Keycloak discovery, token과 JWKS는 컨테이너에서, authorization endpoint는 사용자 브라우저에서 접근할 수 있어야 합니다. 두 기능은 활성화하기 전까지 사용되지 않습니다.

검토와 승인 절차는 항상 표시되나요?

승인 센터는 과거 요청 이력을 위해 유지됩니다. 새 MCP 보호 요청은 관리자가 승인 정책을 활성화하고 해당 작업이 정책에 일치할 때만 생성됩니다.

SMTP를 설정하지 않아도 이메일 발송 완료로 기록되나요?

아닙니다. v0.2.5의 지원 설정에서 SMTP host가 없으면 이메일 capability가 비활성으로 표시되고 digest worker도 시작하지 않습니다. SMTP 관리 설정과 테스트 메일은 아직 지원하지 않습니다.

Outgoing webhook은 프로세스 재시작 뒤에도 재시도되나요?

네. callback 작업과 시도 이력은 PostgreSQL에 저장되며 lease, backoff와 dead 상태를 사용합니다. 다만 post 저장과 queue 등록은 아직 하나의 DB transaction이 아니므로 완전한 domain-event outbox 원자성은 다음 단계입니다.

moyro v0.2.5을 여러 애플리케이션 replica로 운영할 수 있나요?

아닙니다. v0.2.5의 지원 토폴로지는 외부 PostgreSQL에 연결된 moyro 애플리케이션 컨테이너 한 개입니다. Redis fan-out과 multi-replica 설정 전파는 지원하지 않습니다.

moyro native plugin은 sandbox에서 실행되나요?

아닙니다. runtime 업로드와 lifecycle 관리는 지원하지만 native plugin은 서명 미검증 Trusted Native 코드로 서비스 UID, 컨테이너 namespace, volume과 network를 공유합니다. 검토하고 승인한 archive만 설치해야 합니다.
